# 识别与跟踪设计基线

状态：算法设计参考，包含尚未实施的候选方案；不规定当前工程的文件布局、
实现语言或迁移任务。实际接口见 [检测器说明](../src/detector/README.md)，
工程约束见 [AGENTS.md](../AGENTS.md)，板端流程见 [调试手册](DEBUG_GUIDE.md)。

## 1. 两个工况

| 项目 | 启动/重捕获 | 跟踪/接近 |
|---|---|---|
| 先验 | 不知道目标在哪 | 有上一时刻状态和尺度 |
| 扫描 | 全图粗筛 | 预测 ROI |
| 算法 | 二值图 → 候选 → 时间窗确认 | 连通域/形状 → 尺度状态滤波 → ROI |
| 主要风险 | 坏点、反光、贴边亮块 | 出框、急机动、干扰物和尺度突变 |
| 正常退化 | 暂不输出目标 | 放大 ROI，超过阈值后全图重捕获 |

贯穿两态：

1. 识别模块只读带 stride/有效位的输入图像；不重复读取或修改采集缓冲。
2. 单帧不能区分坏点和目标时，用连续帧、位移/尺度物理性和质量做确认。
3. 离群、病态矩阵、非法窗口一律作为“本帧没有有效测量”，不能悄悄污染状态。
4. 识别结果是值类型（坐标、尺度、质量、时间戳、状态、有效位），不把帧指针传进控制层。

## 2. 代码边界

当前检测器位于 `src/detector/`，使用常规 C++ 头文件和源文件，只消费只读帧数据，
不持有相机或厂商句柄。相机的 C ABI 与硬件适配位于 `include/firmware/src/camera/`。
接口、配置和内部状态按所属功能组织，具体声明以源码及检测器说明为准。

下文的瓦片扫描、滤波器和状态机属于设计参考，不代表已实现，也不授权自动改写当前模块。

## 3. 启动阶段：全图和时间确认

### 3.1 瓦片粗筛

默认可用 16×16 瓦片：统计亮像素数、`Σx`、`Σy`、包围盒和质量，邻近瓦片做 8 邻域合并；只对 Top-K 候选做标量精修。二值图没有灰度时，基础 score 是面积；圆度只能作为可选排序项，不能在小目标上硬筛死。

圆度可用离散矩/等效椭圆轴比和填充率的组合，范围 `[0,1]`。不要使用未经验证的 `4πA/P²` 作为小像素目标门限，数字化圆的阶梯边界会系统性低估。

RVV 只是 C 数据面的一个实现选项。必须保留标量参考路径和启动自检，在目标工具链上验证向量掩码类型、归约指令和 VLEN；文档中的历史耗时只能作为待复现实验，不能写成当前基线。

### 3.2 三帧（或配置窗口）确认

候选确认至少包含：

- 窗口帧数与最少命中数；
- 用匀速外推做关联门；
- 相邻位移差（离散加速度）上限；
- 累计位移、半径变化率和质量边界；
- 默认跳过贴画面边缘的候选，避免面积只是下界。

确认成功时用窗口内多点最小二乘初始化位置、速度和尺度速率，随后才允许滤波器成为控制输入。窗口切换到全图/ROI 时清空旧候选，禁止把上一轮目标确认给新目标。

静止常亮坏点与静止目标在二值时空上不可分，必须通过灰度、无光基线或目标外观补充；不要声称滑窗能解决它。

## 4. 跟踪阶段：尺度状态和 ROI

建议状态：

```
x = [x, y, vx, vy, s, vs]ᵀ,   z = [cx, cy, r]ᵀ,   s = sqrt(area / pi)
```

使用实际帧时间 `dt`，夹在合理上下限；时间跳变、长 gap 或无效测量不进入状态推进。预测后保证 `s >= min_radius`。尺度进状态是为了描述“目标均匀变大”，避免每帧按面积开窗造成窗口跳动。

尺度测量噪声可以随预测尺度和质量调度：远距离/小目标更多相信模型，近距离/大目标更多相信轮廓；贴边、形状差或过曝时放大方差。参数应由样本估计，不能照搬 v1 数值。

保护至少两层：

1. 马氏门限拒绝 ROI 内的明显干扰；
2. 连续拒收时有限地放大协方差，允许真正急机动重新接管；恢复后停止放大。

拒收计数和救援计数必须进入诊断，不能只返回 `false`。

动态窗口可写成：

```
W = (kp * s_hat + margin + k_sigma * sigma_pred) * (1 + grow_per_lost * lost_frames)
```

窗口整体平移进画面；目标贴边时标记 `TargetOutOfRoi`、降低质量并放大下一帧，而不是把裁剪面积当成真实尺度。是否退化为全图按**面积占比**判定，不能使用任一维的固定阈值；目标近距离时允许一个大但仍有效的 ROI。

## 5. 状态机和结果语义

```
SEARCH/START
  └─ 连续确认成功 → TRACK
TRACK
  ├─ ROI 命中 → TRACK
  ├─ lost_after 帧无有效测量 → LOST
  └─ 失去超过 rescan_after → SEARCH（清空滑窗）
LOST
  ├─ ROI/全图重新确认 → TRACK（长断时重置滤波器）
  └─ 持续无目标 → LOST，输出 stale/invalid，不输出伪坐标
```

每帧结果至少包含：`timestamp`、`source_frame_id`、中心、尺度、速度（若有效）、ROI、质量、状态、`fresh/held/lost/rejected/out_of_roi` 标志、处理耗时和输入年龄。控制层只接受有效且未过期的结果。

## 6. 诊断和参数

板端最小诊断行应能回答：本帧扫了全图还是 ROI、候选数、命中/拒收/贴边/出框/重捕获次数、扫描耗时 p50/p95/max、帧年龄、队列高水位和内存高水位。高频正常“无目标”只进计数器；硬件/配置错误在恢复边界结构化记录一次。

| 参数 | 影响 | 调参证据 |
|---|---|---|
| 阈值/最小面积/Top-K | 噪声与候选漏检 | 原始 Y/PBM 统计和候选分布 |
| 瓦片尺寸/向量路径 | 合并误差和耗时 | 标量对照 + 板端扫描时序 |
| 确认窗口/加速度门/关联门 | 误确认与重捕获延迟 | 闪烁坏点、匀速/急机动样本 |
| ROI `kp/margin/k_sigma` | 出框率与 CPU 占用 | ROI 面积、出框、p95 |
| `R_scale`/滤波门限 | 尺度抖动与跟随滞后 | innovation/NIS/拒收计数 |
| 丢失/重扫阈值 | 失锁恢复速度 | 丢帧和干扰物试验 |

所有默认值标为 `UNVALIDATED`，配置版本与样本日期随日志保存。

## 7. 验证顺序

1. 主机：只测算法内核的标量参考、几何、窗口边界和固定矩阵；C++ 测状态迁移和错误传播。
2. 交叉：检查 C ABI、RVV 编译、段大小、工作区不足和 `-fno-exceptions`。
3. 板端：先跑帧池/二值化/扫描探针，再接真实采集；验证 cache/DMA、stride、曝光和帧时间戳。
4. 最后接跟踪和控制，保存原始帧、检测结果、状态迁移和失败样本。

不要为了让主机测试通过而加入 MPP/VICAP 兼容分支；真实视觉性能、曝光分离度和 RVV 行为只能在板上验证。
